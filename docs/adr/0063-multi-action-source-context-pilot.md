# 多动作来源说明与独立执行的区分试点

第 21 轮真实诊断中，两个独立视觉热身与一条复合语音观察同时保留，产生重叠
待确认候选。拟在默认关闭的隔离试点中允许模型把一条确实同时介绍多个动作的
语音观察标为“多动作来源说明”，关联已有独立动作，不把该说明再编译为一次
执行；模型仍可能错判，须先完成公共接口反例和真实质量对照，不代表已批准默认启用。

## 与现有决定的关系

ADR-0053 的每个观察 ID 恰好一次、模型判断身份和程序保护继续有效。试点仅为
来源说明增加多目标引用，不能把同一普通观察复制进多个训练组，不能将来源说明
伪装成预告/回顾或不训练的噪声。ADR-0055/0061 的教学合并与所有编号、变式、
侧别、轮次、时间和参数保护不变；正式工厂、默认提示与外部方案合同暂不改变。

## 拟定限制

- 只在显式试点配置启用时提供新角色与引用合同，不新增模型调用。关闭时保持
  当前行为与原模型输入；不使用词干、同名或知识库命中代替动作身份判断。
- 模型必须明确判为同一段说明涉及至少两个已存在、相互独立的当前动作；引用
  本次输入的视觉观察 ID，各自所在训练组已通过原保护。不能新建时间、动作或目标。
- 复合动作名称本身不能证明这是一段多动作说明。必须有运行内、同来源、带时间
  且可核对的完整语音原句引用，保留条件、否定和前后指代；短 `evidence_text`
  不能未经原转写匹配就充当原句。需要补足这部分输入时须在实现规格中明确，
  没有完整来源支持则继续原行为，不让模型凭两类器械词自行补出说明。
- 每个引用目标必须有正长度的时间关联，目标视觉范围联合覆盖说明范围，不能
  用未观察空白、被拒绝组或时间仅接近来完成覆盖。前后再次执行、单动作跨块
  教学、真实组合动作、侧别/编号含糊均不能靠该角色自动消除候选。
- 带明确训练参数或参数冲突的复合语音暂不适用：保留原待确认候选和全部不同值，
  不把“都做若干组”等范围要求静默复制或丢掉。
- 原来源范围随关联目标保留；不扩张默认播放选段，不分割原话或伪造更细时间。
  共享说明不增加独立证据票数，不改变目标的待确认状态，不新增执行次数。
- 说明上的提醒不自动复制、搬运或按时间分发；引用关联不是提醒归属证明。
  目标组本来合法的提醒保持原样，复合说明内无法确认归属的提醒明确保持未采用。
- 未知/重复/跨来源引用、目标不够两个、目标本身未通过原校验、覆盖缺口、参数
  歧义或模型 unsure 时回到原候选保留路径；失败、超时和取消遵守现有语义。

## 验证顺序与停用条件

沿用 Provider 输出 → 候选融合公共接口，外部 HTTP 替代模型响应。先复现
“两个视觉动作 + 一条复合语音 = 三个候选”，再测试两个独立动作保留且来源
不丢；反例覆盖单动作、组合动作、不同编号/变式/再次执行、语音带参数、缺目标、
时间空白、引用无效和目标冲突。程序只能保证引用与保护，不能证明模型语义正确。

通过后才在同一份瞬态上游证据上比较旧/新合同，不以不同新鲜运行做因果结论。
复合说明被误消除、独立动作减少、参数丢失、提醒越权传播或确认状态被放宽均为
停用项。此试点不解决所有漏识别，也不替代原句提醒选择的单独质量门槛。

## 隔离实现合同（2026-10-04）

本地试点使用显式 `source_context_model` 注入；未注入时不发送原句，原输入预算、
分组 schema 和正式工厂保持不变。开启后仍只作一次分组调用，使用独立内部
`ContextualGrouping` 合同；`shared_sources.member_id` 与普通组成员共同满足每个
观察恰好一次，不进入外部 HTTP/SSE 或方案持久化合同。

`SpeechSourceContext.bind` 在内存绑定来源 ID、完整语音/视觉观察快照和完整转写句。
每次调用生成新的引用 ID；源或上游快照不符时不发请求。整体输入仍受 64KB 限制，
超出时明确保留候选，不截断原句。仅接纳引用完整覆盖语音观察、且目标视觉连续
覆盖相同范围的说明；参数冲突目标不接纳。共享原句仅提供来源关联，不进入目标
默认回放范围，不增加证据确认票数，不搬运提醒。

语音合同本身没有结构化编号/侧别字段；原句中的编号、否定、变式与轮次仍依赖
模型理解。此试点不新增关键词拆分器，也不能宣称程序已证明这些语义。
不同名称只是必要的保守检查，不证明两个目标实际独立。正式启用决定仍为 proposed，
须在同一份真实上游输入上完成旧/新对照并核对这些停用项。

## 启用态提示合同修正（2026-10-04）

原试点仅追加共享来源说明，但保留了旧提示的“所有 ID 必须进入 groups”和
“语音只能 exercise/uncertain”表述，与新 schema 的成员归属冲突。启用时先将
这三段输出/成员/语音角色要求替换成联合归属合同，再追加来源条件；其余动作
身份、时间、侧别、参数和提醒要求不变。关闭态完全不改提示或请求。

公开 HTTP seam 使用仓库实际提示文件验证启用态不再发送互相冲突的旧要求，
关闭态与原输入逐字相同；通过测试不代表模型已正确采用新角色。接着在相同
瞬态上游上比较旧追加版和修正版，不同时改变模型、schema、引用或接纳条件。
