# 视觉来源类型与可见编号约束

状态：2026-09-30 本地修复，关联 #37/#6。未合并、未部署。

## 证据

真实 eval-07 全链路中，视觉模型给出 15 条提醒，4 条错误地声明为 speech，
随后被视觉验证器拒绝。提示词已要求 visual，但共享 SourceTip 的请求 schema
仍允许 speech/visual 两种类型。

eval-08 的一次完整运行中，模型提出 6 组，程序因两组不同数字编号拆回 10 个候选。
这不是 ADR-0056 已处理的数字/中文等价格式。融合观察中的 sequence_label 仅来自
视觉支路，语音观察此字段固定为 null。尚不能据此断言每个错误编号的形成过程。

## 决定

- 视觉请求的 EvidenceSpan.type 限定为常量 visual，覆盖视频和联系表两种入口。
  接收到错误来源类型时，原校验仍丢弃该提醒，不改成 visual，不删除有效动作。
  不改变公共 SourceTip 合同、语音请求、融合请求或永久存储。
- 视觉 Skill 1.6.1 明确区分画面编号与返回数组序号。禁止按片段出现顺序计数、
  在分块边界重新编号或推算缺失编号；没有可读动作编号时返回 null，但保留动作。
  组数、次数、倒计时和技术步骤编号不属于动作编号；明确侧别/轮次/变式仍保留。
- 不放宽融合中的编号冲突保护、时间连续性或动作归属校验；不由知识库补编号。
- 本批不变更 Provider、生产超时或演示入口。原句编号选择仍遵守 ADR-0059 默认关闭。

## 验收与限制

Provider 公共调用的 HTTP 请求断言先红后绿；模拟不遵守约束的响应，确认错误来源
提醒仍被拒绝、正确视觉提醒和动作仍保留。真实复测单列报告。

请求 schema 与提示词不能证明模型阅读正确。分块自行编号只是待检验机制，不能
把一次复测改善写成稳定解决；可见编号 OCR 和动作归属仍需质量复核。
