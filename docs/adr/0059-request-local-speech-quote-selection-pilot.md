# 本次请求内的语音原句编号选择

状态：2026-09-30 本地实验切片。用户授权继续修复、使用真实音视频及现有 Provider，
以解决问题为目标；没有授权合并、部署或更换演示服务。本试点默认关闭。
关联 #37/#23，补充 ADR-0058；不改变正式归属与分组合并门槛。

## 问题与范围

同一份真实转写的对照中，完整原句提取会输出零条提醒。只补充上下文说明虽有时
增加提醒，但出现动作数量减少及重复试验波动，未作为产品修复接入。
要求模型同时判断归属、逐字复制原文及复述时间，还存在可避免的复制失败路径。
这里减少复制任务，不宣称已经解决 ASR 正确性、动作归属或重复候选问题。

## 决定

- 为 Ark 客户端增加仅显式构造可开启的 `select_speech_quotes`，默认 false；
  产品工厂和设置不启用，现有 API、方案、旧数据及视觉 Provider 不变。
- 开启时，当前语音请求为合法 ASR utterance 分配带随机请求域的 ID，原文及完整
  时间仍在本次输入中。ID 不能由调用方或模型指定，上一请求的 ID 不可在本次命中。
- 沿用一次语音理解调用，动作字段保持原合同。仅提醒的内部传输格式改为
  `{utterance_id, category}`，模型不能提供提醒正文或时间。程序查表回填原文和完整
  时间，再进入原有整句匹配、动作/窗口时间、安全和后续融合归属审核。
- 不扩大 80 字限制，不取子串、不拼接、不用知识库补写。ASR 整条不等于语义完整；
  模型仍需检查相邻动作介绍、条件、否定和转场。有上下文不足就不选择。
- 动作提取与提醒选择分开：无提醒不应删动作；热身、放松、可选有氧仍需按原合同提取。
- 非法 ID、重复选择、额外正文/时间字段或非法选择结构令该信号提醒为空，不删除
  有效动作；无法构成合法 SourceTip 的单条（如超长或类别错误）省略。原动作字段
  仍严格解析，不以提醒容错掩盖动作错误。有效但时间越界或不安全的原句仍被原门槛拒绝。
- ID、转写、模型响应及引用表只留在本次调用内，不新增存储或日志。最终仍输出原有
  SourceTip，编号不是音频核验、语义归属或专家审核证明。

## 验收

测试位于用户已确认的 Provider → 候选融合接口，检查 HTTP 模型请求及最终候选：
完整原文/时间、否定/条件/侧别保留、跨请求 ID、未知/重复 ID、模型正文/时间注入、
超长、不安全和动作范围外原句；提醒拒绝时有效动作及参数仍在。默认路径的既有
回归继续运行。

真实对照必须同时看动作保留与提醒保留。上游通过数量不等于最终训练提醒正确，
完整链路仍需复测；分组拒绝仍会清空该组提醒，不因此放松身份或编号校验。
只有数量增加不能批准正式启用，试点结果与现行产品能力分别报告。
