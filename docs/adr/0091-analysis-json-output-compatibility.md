# ADR-0091：视频分析的显式 JSON 输出兼容模式

状态：2026-10-19 单次产品链路通过，重复运行稳定性待解决；默认模型与默认输出格式保持不变。

## 问题与证据

现有 Mini 路径在指定 68 秒视频上仍混入片头背景、概括热身，产生八至九项候选。
较强的同服务商 Pro 2.1 模型在原 JSON Schema 输出模式下连续返回非法 JSON：
响应声明 completed，但对象末尾缺少分隔结构。不能修补后当作有效模型输出。

隔离对照将相同模型改为 JSON Object 输出，并把同一 Schema 放进指令。
连续两次完整分析得到两个热身、四个正式动作、一项可选有氧，分别约 51.86 和
53.25 秒；四个正式动作的 4 组、8–12 次保持一致，有氧只有语音来源、无伪造示范。
这两次使用原有本地模型校验，不构成新兼容模式的最终验收。

## 决定

增加 `ARK_ANALYSIS_RESPONSE_FORMAT=json_schema|json_object`，默认 json_schema。
仅作用于普通语音理解、视觉定位及候选融合；个性化、语音控制、提醒与独立字幕试点
保持原输出格式。模式显式选择，不在失败后自动重试或降级，不修补非法 JSON。

JSON Object 模式仍发送原 Schema，要求字段齐全。返回后校验 completed、无拒绝/
错误/未完成原因、store=false 与格式一致，再按原 Schema 验证类型、必填字段、范围
及额外字段，最后运行原有领域模型和时间/来源/分组校验。验证前沿用 ADR-0057/0058
的两项可选提醒隔离：无效或缺失的提醒 ID 选择置空、超长语音原句整条省略，
不修补动作或参数字段。该模式不改变参数、证据来源、
动作边界或不确定性规则，也不启用共享来源试点。

模型路由继续由现有配置明确选择。本机预览用于复测同服务商 Pro 2.1 模型；
线上默认模型仍不变。原始视频、转写、请求与模型响应继续只在运行中临时使用。

## 验收

HTTP 边界测试覆盖正常语音/视觉/融合、缺失动作字段、字符串冒充数字、拒绝与
未完成响应、可选提醒隔离，以及个性化请求格式保持不变。

首次接入更改了 Schema 指令措辞与序列化，仍出现非法 JSON。恢复到隔离实验已验证
的请求形态后，实际产品管线完整运行约 52.34 秒，得到相同七项。
随后从真实浏览器导入源视频，完整经过模型分析、个性化、手动编辑、保存恢复、
16 组执行及结果反馈，流程通过。随后重复运行仍遇到视觉非法 JSON，返回 partial；
不能以首次成功宣称稳定性通过。降低温度仍失败，深度思考超过 90 秒本地窗口预算，
原有分段读取又遇到可选提醒额外字段导致校验失败，均未推广。模型输出没有截断、修补或按数量删行。
本地样本验收不扩展线上延迟、长视频能力或其他视频的质量结论，详见
[真实验收记录](../design/trainpal-real-ai-acceptance-20261019.md)。
