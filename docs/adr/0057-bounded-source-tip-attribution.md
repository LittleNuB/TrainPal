# 来源要点的有界归属审核

状态：已接受，2026-09-20，依据用户同意诊断后的链路优化；关联 #23/#6，依赖 #35。补充 ADR-0053/0054，不改变动作身份、时间、编号或参数保护。

## 缺口与决定

上游将要点嵌入动作观察，现有视觉校验只检查时间包含；语义分组输入不含要点，最终直接汇集成员的要点。因此上游误把相邻动作的收尾字幕挂入稍早开始的下一动作时，后续无法审核。合成复现证明此防护缺口，不代表还原了未保存的真实模型响应。

沿用一次现有语义分组调用，增加要点归属审核，不增加 Agent、Provider 请求阶段或自动重试。每条上游短要点以本次观察内稳定 ID、原文、类别和来源范围进入模型；所在观察仅为上游归属假设，不是已确认事实。模型结合完整观察序列判断，并为每个正式动作分组返回 `accepted_tip_ids`（最多三条）。只选当前组成员已有的要点，不改文字、类型、时间、参数或动作范围；不跨组搬运。相邻动作收尾、提前讲解、回顾或归属不清的要点不选。需恢复被错挂的要点属于后续独立能力，本批宁可无提醒，不伪造归属。

代码验证所选 ID 唯一、来自本组、来源类型与原观察一致且时间仍位于原观察内；任一非法选择使该组要点为空，不破坏动作结果。只有通过原有动作分组校验的正式组可输出审核后的要点。缺少选择、模型不确定、分组拒绝、参考关联和融合失败/预算不足时，不透传未审核要点。原始动作与参数/来源保护保持；不因为提醒缺失把整份方案判失败。

要点证据只在本次运行内暂存；最终公开合同仍为最多三条原有 `SourceTip`。不新增持久化未审核材料，不清除或改写旧方案已保存要点。模型仅审核归属，不被描述为重看了原视频或人工核验；若上游和审核同时误判，本机制仍可能出错，真实质量待复测。

## 验收

使用既有 Provider 和候选融合公共接口，在 HTTP 模型边界替换外部响应，不测试私有方法。覆盖相邻动作收尾被拒、正确要点保留、未选/非法/跨组/重复 ID、不同编号、再次执行、语音/视觉要点、失败/超时/预算不足、原文及来源不变和参数冲突保留。真实模型准确性和耗时另行授权验收；本批零收费调用。
