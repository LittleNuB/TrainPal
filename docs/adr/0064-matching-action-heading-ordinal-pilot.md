# 动作标题与纯编号格式兼容试点

2026-10-04，关联 #6/#37。用户授权当前 Goal 的必要隔离修复。第三次完整 68 秒诊断
在同一份上游内复现：一条视觉标签为完整的编号四写法，另一条为可见标题
“动作四：大剪刀下拉”；源视频第 53 秒画面已核对。现有 ADR-0056 仅允许完整纯
编号字符串，因而将二者判为冲突，同次分组拆回并暂不采用提醒。

## 与旧决定的关系

本试点显式扩展 ADR-0056 的纯字符串格式范围，不取消编号身份保护。仅在构造时
设置 `allow_titled_sequence=True`；默认 False，正式工厂不变。它不影响模型如何
分组，不补写标签，不修改 Provider 输出、播放范围、参数或确认规则。

## 接纳条件

- 标签形如“完整合法序号：完整动作名”，中英文冒号均可；左侧必须已能按原规则
  完整解析为序号，不能在任意文本内找一个数字。
- 右侧去掉首尾空白后，必须与当前组内**所有视觉证据的原始非空 action_name**相同，
  不使用已转成占位或翻译别名的候选显示名。不同名、
  无名、变式、侧别、轮次或其他修饰不能通过删字、别名/知识库或模型改名来匹配。
- 满足以上条件只在身份比较时使用左侧序号；所有原标签、动作名及证据不改写。
  其他标签仍使用原完整字符串身份，所以不同数字或不匹配的标题仍冲突。
- 正式分组及预告/回顾关联共用此规则；后者仍执行原角色、方向与参数校验。
- 语义模型必须先判断同次示范；时间、组外边界、再次执行、参数冲突及提醒来源
  校验不变。仅有同名或同序号不能触发跨组主动合并。

## 验证

沿用已确认的 Provider HTTP → 候选融合 seam。先复现 3 个待确认候选和提醒丢失，
再验证只剩一个同次动作、参数和原提醒保留、默认观看仍是原视觉片段。反例覆盖
不同编号、标题/成员名不一致、侧别、轮次、未知格式、模型不确定、再次执行、
缺失动作名及参数冲突；默认关闭与开启对照。

真实验证应在同一份瞬态模型响应上离线回放新旧校验，避免把模型随机变化当成
代码效果；实际名称未满足条件则继续拒绝，不能为迁就本样本扩展别名。当前证据
只证明第三轮的标题格式现象，不能追溯解释此前未保存的编号。

该试点不解决上游错误编号、语义误判、共享说明不被采用或热身分类不稳定。接入
默认路径需真实复评及反例通过，不以专项测试通过宣布整个 Goal 完成。
