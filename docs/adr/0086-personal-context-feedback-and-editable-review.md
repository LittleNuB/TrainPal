# ADR-0086：真实个性化上下文与可编辑建议

- 日期：2026-10-09
- 状态：Accepted；按用户批准的 ADR-0085 实施计划 C1/C2 落地
- 关联：ADR-0019、0046、0049、0085

## 决策

1. 确定性调整升级到 `adjustment-policy.v2`。提案包含 `adjustment-context.v1` 快照；训练经验、当次可用分钟、精力、匹配的反馈、上下文 revision 和策略版本都参与输入指纹。训练经验由用户填写并保存；时间与精力只用于当次提案。
2. “有点累”时不加量；挑战方向按更容易完成处理，并允许原边界内的休息延长。控制用时使用实际目标，目标已满足时保留方案；达不到时展示可达到的预计时长。ADR-0046 的自动调整字段、幅度、整份预计时间 ±20%、初学者、反馈和不适停止规则保留。
3. Dexie v6 增加 `actionFeedback` 表。反馈关联冻结记录、原方案 ID、动作 ID、动作 revision、名称、模式、来源和片段。只读取完全匹配的动作；重识别、复制方案不按名字继承。反馈可修改或清除，不改冻结记录；本地数据清除包含此表及 store。
4. 旧资料迁移时训练经验为 null；不从 GYMTI 或身体资料推断经验。可选资料保存不得丢失已填写经验。教练风格只改变表达。
5. `adjustment-review.v1` 是与提案 ID、基础 revision/fingerprint 绑定的页面内副本。原始提案不变；数字只写入审阅副本。取消或刷新丢弃尚未应用的手改值，回到基础方案；保留的原始提案可重新生成。
6. 应用前校验提案策略版本、基础方案、字段原值及来源、审阅字段集合和手动数字合法性。未编辑建议为 `personalized`；手动覆盖为 `user`。沿用既有原子存档与失败回滚，重复点击和清除期间不能二次应用。
7. 恢复基础方案只恢复仍等于已应用 AI 值且来源为 `personalized` 的字段，保留手动值。资料更新只提示上下文已变；基础方案改变使提案失效。
8. 旧 v1 提案可读取，不可直接应用，需重新生成。无需新增模型调用、聊天入口或训练执行器状态。

## 验证

`personalized-editing.spec.ts` 覆盖上下文差异、目标边界、反馈身份隔离、独立写入/清除、v5 资料迁移、审阅来源、原子失败回滚和旧提案拒绝。既有 `draft-store.spec.ts` 保留并发、恢复、存档和失效回归。`sport-ai-delivery.spec.ts` 验证真实页面编辑、刷新、训练与动作反馈，使用隔离的合成分析证据。

`plan-personalization-view.spec.ts` 覆盖反馈清除后的展示、慢保存时上下文锁定、初学者调整范围，以及审阅错误在折叠后的保留和应用前首错聚焦。输入阶段不引用旧建议的历史反馈；已删除反馈不再出现在原提案的展示依据中，原始提案快照保持不变。
