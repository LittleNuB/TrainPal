# 视觉读取JSON语法模式兼容性试点

2026-10-05，#6/#37，基线d29f562。沿用当前目标的隔离修复与验证授权，不代表
正式启用或Provider切换。前批真实读取有非法JSON；合成对抗输入中完整读取schema
也出现违规，不能将对抗失败率当作真实质量或唯一根因。

- 显式`visual_reading_format="json_object"`且须启用独立字幕。默认json_schema，
  工厂、设置、公开API、演示及旧方案不改。仅`read_visual_evidence`使用该模式；
  语音理解、字幕整理及语义融合仍按原schema请求。
- 模型仍读取同一视频块和同一动作/字幕要求，不新增模型节点、请求、重试或存储。
  原完整schema以请求内JSON说明追加到读取指令，API格式仅请求JSON对象；模式
  只约束语法，不作为字段、时间、内容或归属正确的证明。
- 接收metadata必须completed、store=false、无拒绝/错误/未完成，并匹配实际请求
  的json_object格式。随后使用原完整schema及模型校验，拒绝非法JSON、非有限数、
  缺字段、未知字段、错误类型/枚举、容量和越界；不修补、转型或删除坏值。
- 保留ADR0076的点字幕隔离与原时间。动作观察仍为正时长，字幕独立且不裁剪；
  原文仅本次内存。后续绑定、完整覆盖、参数冲突、身份及提醒归属保护均不变。
- 这不是已验证修复；若真实读取没有改善，报告失败，不默认接入。提示变长的
  token成本和耗时需据实记录，不宣称更短或更快。

metadata/拒绝/未完成仍失败关闭；默认及其他模型请求不变。完整check、E2E、
