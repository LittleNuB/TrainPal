# 视觉来源类型由输入分支绑定的隔离格式

2026-10-04，关联 #6/#37，补充 ADR-0065。用户授权当前 Goal 内的必要隔离修复；
不切换 Provider、不启用产品默认、不修改融合时间或共享说明判准。

## 直接依据

shared-29 在208秒完整分析的第四个视觉块失败：三条提醒的 evidence 对象均缺
type，响应元数据正常，JSON解析成功，实际schema不通过。前三块已通过，未进入
融合；无法回答本次片尾遗漏在哪一层，不能把此失败算作漏识别或重放旧响应。

视觉 Provider 分支只接收视频或视频帧图，本身已决定来源类型为 visual。让模型
逐条重复输出固定类型没有增加来源证据，却引入一个可遗漏字段。来源类型不能
证明字幕内容、时刻或归属正确，这些要求继续独立校验。

## 决定

- 增加显式内部格式 `visual_parameter_context_format="flat_branch_source"`，必须
  同时显式开启 `visual_parameter_context=True`。默认 nested 和已有 flat 完全
  保持；工厂、环境变量、公开 API、方案数据不接入此新格式。
- 新格式沿用flat次数用途字段，视觉提醒 evidence 只要求 start_seconds 和
  end_seconds；schema 不允许模型返回 type（无论 visual、speech 或其他值）。
- 提示按已知且唯一的格式片段同步改写，保留调用方后缀和所有语义约束。版本漂移
  或重复片段时在发请求前拒绝，不能以矛盾提示继续。
- 先对实际返回执行原metadata/JSON/schema检查；通过后仅按分支固有属性绑定
  `type="visual"`，映射回原内部模型。不是猜测内容来源，也不是对旧格式失败
  自动补值：旧flat仍要求type且拒绝缺失，旧响应不能追认为新合同通过。
- 提醒文字、分类、起止时间、次数用途及出处等仍由模型输出，缺字段、类型错误、
  越界、不完整用途、非法值依旧走原拒绝/安全过滤规则。最多三条、完整必要短句、
  原时间坐标、动作/编号、参数和归属保护不变，不增加请求或自动重试。
- 不改变ASR来源、提醒审核权限、原文保存策略、训练执行、前端或存档结构。

## 验证与启用门槛

沿用已确认 Provider HTTP 公共边界，先观察新格式测试失败，再实现固定映射。
验证原内容/时间保留、旧flat继续拒绝缺type、新格式拒绝模型自报type及其它
缺失字段；视频帧图的绝对时间与调用方后缀必须保持。运行完整工程/API/E2E
检查以及Standards/Spec双轴审查。

这是针对已知固定字段失败的合同改进，不代表其他结构错误、动作重复、片尾
遗漏或可靠提醒归属已解决。真实复评在新格式明确启用后另作记录，严格区分
新合同符合性与旧合同原生符合性；正式启用仍取决于完整Goal验收。
