# 可见编号字段澄清试点

2026-10-04，关联 #6/#37；承接编号等价保护 ADR-0056、标题兼容试点 ADR-0064
及 `docs/design/trainpal-ordinal-expression-probe-20261004.md`。用户授权 Goal
内必要隔离修复；不切换正式 Provider、不启用产品默认、不改变合并规则。

## 原因

现有视觉提示同时说 sequence_label 是完整标题转录与明确序号转录。私有同输入
ABBA 中旧提示有一次输出标题编号，澄清提示两次输出纯编号；两次后续完整 68 秒
分析无编号冲突并保留目标提醒。样本有限且完整运行上游不同，不证明稳定改善。

## 决定

- 仅显式构造 `ArkResponsesClient(clarify_visual_ordinals=True)` 启用，默认 False。
  不增加环境变量、工厂接入、公开 API 或持久化字段，不修改已有方案。
- 替换已知视觉 Skill 1.6.1 的编号段落：编号与普通动作名分工，完整标题进入
  visual_cue；侧别、轮次、变式仍须进入 sequence_label 和 action_name。不能可靠
  分开时保留完整标签，不能为纯数字删掉限定词，不猜缺失编号或按数组位置编号。
- 只替换已知完整段落一次，内容漂移、重复或缺失时在 HTTP 前报固定配置错误。
  保留调用方后缀、其他识别/参数/提醒说明及原 schema；视频和 contact sheet 均适用，
  与原输出、nested/flat 次数用途配置兼容。语音与分组提示不受影响。
- 这只影响模型输入，不改写模型返回的编号、名称、描述、时间、参数或提醒。
  原始限定标签直接进入融合，仍要求同次示范及原时间/身份/参数/来源校验。
- 不改变 ADR-0064 的严格全名匹配，不新增别名放行或通用时间容差。模型仍可能
  漏掉限定词或读错编号；代码保留测试不能证明模型真实识别正确。

## 验证与默认启用边界

沿用 Provider HTTP → 候选融合公共 seam，先复现入口缺失，再检查原响应保留、
语音/分组不变、默认不变、其他指令/载荷不变，以及不同编号、侧别、轮次、变式
不会被错误融合。配置漂移反例必须在网络前拒绝。与私有原适配器作零网络完整
载荷对照，然后运行完整工程检查、E2E 和接口一致性检查并双轴审查。

先前私有真实结果仅支持迁移，不替代迁移后同代码重复 68/208 和 39 反例验收。
还须核对真实限定词、提醒语义归属与完整来源；不因编号无冲突或候选数正确
宣布整个 Goal 完成。热身复合说明和视觉时间估计是独立剩余问题。
