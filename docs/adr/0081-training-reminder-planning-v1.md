# 训练提醒编排 Skill 与 ReminderPolicy.v1

状态：本地实施中，2026-10-06。依据已批准 Goal v2 第4/5节及用户提醒调度原则。
关联 #23/#37、ADR0052/0080。不代表自动播报或手机验收已完成。

## 输入输出与测试边界

沿用 Goal 已确认的公开边界：当前方案与审核要点 → Skill 提醒安排。首个实现提供
`TrainingReminderPlanner.plan(ReminderPlanRequest)`；通过实际 Provider HTTP 边界的
测试响应检验模型排序与确定性预算，不测试私有辅助函数或模拟内部模块。
后续场次/缓存通过 store actions 验证，声音通过可见流程及真实可听结果验证。
下一纵切以 `/api/v1/training-reminders` 的实际HTTP合同、现有草稿保存/重开与
场次创建/恢复操作为边界。API只在显式注入编排器时可用；暂不接默认工厂或演示。
缓存只保留结构化已审核输入、版本绑定及合法要点ID安排，不保存模型原文。
输入必须仍匹配当前方案动作、来源和训练量；模型失败不作为模型成功缓存。
旧数据无新缓存时沿用原流程，不推断其要点已经审核，场次开始后不自动补安排。

本地接入采用可选 `reminderCache`（结构化输入与已校验安排），不新增表或永久任务。
审核通过现有草稿 store action 明确指定采用的要点；确认动作名称不隐含审核。
动作身份版本与方案内容版本分开：改名或复制动作撤销旧审核，修改训练量只使安排
失效。成功安排随原方案存档/重开/刷新保留，新场次复制冻结；记录沿用场次快照。
同源 HTTP 最多两个在途编排请求，超出立即返回429，不排队；取消释放名额。
提醒HTTP在读完请求体后同时等待编排与ASGI `http.disconnect`；浏览器断开时取消
本地Provider等待并释放名额，不返回降级成功。两个子任务均在终态取消/回收；这不
改变Analysis Run离页、刷新或SSE断开仍继续的已有合同，也不保证供应商撤销计费。
这不是分析容量或用户配额变更。新接口默认未配置；前端审核界面与播放偏好已在
下述可见批次接通，声音执行代码在下述批次接通；复制/记录复练的新身份绑定已在
下述合成旅程批次验收。真实听取仍待完成，独立入口在下述批次验收，不以 store action、
安排保存或合成完整旅程通过代替真实分析与可听纵切。

输入绑定方案 ID/版本、动作 ID/版本、真实组数/次数或时长、已确认播放偏好。
要点带稳定 ID、审核状态及审核时的动作/来源绑定；缺审核依据默认不可主动播报。
确认动作名称不是提醒审核；旧要点可继续显示，不批量升级审核状态。
输出绑定完整输入指纹及合同/Skill/策略版本，只引用既有要点 ID，不含改写正文、
新来源时间或训练参数。成功安排的缓存、冻结场次与执行接入另按 Goal 完成。
合同 `training-reminders.v1.1` 的输入指纹在校验后的默认值上计算：包络为
`{contract, skill, policy, input}`，对象键排序，数组顺序保留，紧凑UTF-8 JSON后SHA-256。
布尔值保持布尔；整值数统一编码为 `{"$integer":"十进制整数"}`，非整值数编码为
`{"$float64":"IEEE754 binary64大端八字节的小写十六进制"}`，避免Python/浏览器的
1与1.0、科学计数法等JSON表达差异。浏览器不能准确表示的整数不接纳安排。
这只改变哈希规范，不改变Provider wire或训练量边界。前端核对实际输入指纹，
旧v1安排失效但方案和要点可读；缓存校验为异步，切换/编辑/取消后旧结果不能报告
就绪或进入场次。新场次在异步校验前复制完整草稿，避免混用两个编辑版本。
共享的明确合成测试向量见 `contracts/fixtures/training-reminders-v1.1.json`，预期值
由手写规范化包络的独立SHA-256计算取得，不在测试断言中重算生产算法。
本 Skill 请求最多200个动作、每动作五条，完整输入最多64000字节；超过时明确失败，
不裁剪内容或提高容量。调用方可继续文字跟练，不把编排失败当成方案不可执行。
入口、实际模型排序载荷及 Ark 发送使用同一紧凑 JSON 表达并按 UTF-8 字节校验；
投影后的载荷也须完整校验，不能让额外空格或绑定封装使实际输入越过容量。

## 初版策略参数

- 每动作最多五条不同的已审核视频要点；一次编排中每条最多安排一次，不默认每组
  重复。来源、动作、版本、完整时间范围或安全校验不合法时不进入主动提醒。
- `setup` 只安排在动作准备阶段，最多一条；其余准备内容保留文字可查。其他类别
  在训练阶段使用。第一组/新动作仍需用户准备确认，提醒不改变训练状态。
- 次数型只安排在真实的组开始事件，每组最多一条；不生成估算秒数或自动计数。
- 计时型每组可用开始事件及至少30秒间隔的实际活跃时间触发，结束前10秒不新增
  提醒。短于或等于10秒的组不安排训练阶段语音，文字仍保留。
- 多组先为不同组分散要点，再考虑长组内的额外时点；总数仍受已有可靠内容约束。
  例如15秒单组的五条训练要点只安排一条，60秒三组最多五条，次数型三组最多三条。
- 30秒与10秒是可测试、可调的初版产品参数，不是科学训练或安全阈值。声音执行器
  还需按实际播报长度、倒数、原声和冷却检查，冲突时跳过，不补播或改变训练。

## 模型与降级

Skill 只为每个合法动作排序全部已有要点 ID。不得创建内容、时间、训练量、审核
结论或跨动作移用要点。确定性策略负责阶段、组号、时点和预算。
模型最多一次无重试请求，现有 Provider、不新增服务；错误、超时、缺失/重复/
未知 ID 或过期绑定时明确使用规则排序，不把它算作模型成功，不阻塞开始训练。
偏好未确认、关闭自动播报或无可靠内容时不调用模型。无需模型的规则调用也可用。

开发先使用明确合成的合法结构化要点；不为这一模块调用真实音视频分析。
不接入演示15176、不切换正式 Provider、不推送/开PR/合并/部署或开放网络。

## 后续必须完成

### 可见接入批次（2026-10-06）

沿用已同意的可见流程、store actions、HTTP和浏览器音频边界。动作编辑中逐条核对
来源要点，默认不选；确认动作不自动核对提醒。方案概览只增加一个可关闭的播报
开关，首次明确开启才保存偏好。旧偏好缺字段时关闭，不迁移历史审核结论。
审核、训练量或偏好变化使未开始的安排失效；编排/保存失败显示文字可用，不阻塞
开始，不自动重试。离页、编辑、关闭或开始训练时取消未完成请求；已开始场次
只用冻结的合法安排，不在训练中补入迟到结果。

开始训练的公共store先校验完整来源草稿的安排，再排除待确认动作；冻结输入仍
保留完整绑定，执行只读取场次里实际纳入的确认动作。不能为保住缓存批准待确认
动作，或重新哈希一个从未编排过的子集。复制/复练的新方案必须重新绑定，旧安排
不得冒用新方案ID。可见审核批次本身不包含声音验证，不能将“安排已保存”标成声音已通过。

审查补充：同设备偏好写入串行使用最新值，关闭播报在当前应用内立即生效；即使
存储失败也不恢复旧开启态，并提示重试以避免下次完整重载读到旧设置。挂起状态
由store持有，编辑组件卸载不会留下永久开练锁。仅提醒缓存未保存时，开始操作可
省略该可选安排后保存原方案，以文字跟练；实际方案仍保存失败则继续阻止开练。

### 声音执行代码批次（2026-10-06，代码检查与独立审查通过，真实听取待验收）

`TrainingView` 使用场次冻结的合法安排，不发起模型请求。重新核对方案安排指纹、
动作/来源/版本、训练量与已审核要点；只有既有合法 ID 可以触发。文字保留完整原句
和出处，可以手动查看下一条及全部内容。声音使用浏览器提供的本机中文语音，明确
要求 `localService=true`，不静默外发到新远程 TTS 服务；不存在或尚未加载时使用文字。
声音列表后来就绪只作用于未来时点，不回放错过的提醒。
参见 [本机与远程语音区分](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisVoice/localService)。

执行参数 `ReminderExecution.v1`：准备类只在首组准备/新动作准备；训练类只在真实组
开始或合法活跃时间交叉触发，迟到容忍最多2秒。活跃训练中的语音开始之间至少30秒
实际已练时间，休息与倒数不算练习间隔；组末10秒停止语音。用每秒4个字符、额外1秒、
最少3秒的保守产品估计判断一句能否在静默期前说完，超过12秒的句子只显示全文，
不截断原句；浏览器排队/其他语音占用时跳过，12秒未终止的请求取消并退回文字。
这些是初版产品参数，不是科学训练阈值或已测量的设备语速。

语音开始事件才显示正在播报并压低视频原声至原音量20%；仅请求成功/排队不算已
开始。结束、取消或失败恢复原音量。倒数使用既有音效，优先于提醒；两者共用压低
音量所有权，避免重复相乘或恢复错视频。点击暂停、完成、跳过、明确提前结束，
以及后台/离页时先取消声音，不等待训练保存；取消不写训练进度。静音保留既有语义，
另有关闭自动提醒的操作，不影响视频原声。关闭偏好保存失败在当前应用仍保持关闭，
并提供重试保存提示。
后台取消监听在训练恢复及媒体加载前注册；来源读取挂起不延迟取消，卸载后迟到的
初始化不再注册监听或启动计时器。关闭或静音期间已遇到的提醒仍标记为处理过，不在
重新开启后补播。

浏览器 `sessionStorage` 只保留当前页签的一个执行记录：场次 ID、完整安排 SHA-256、
已处理提醒的数组位置、上次训练语音开始时的累计已练时间。最多1000个位置/8192字节，
无提醒正文、录音或模型输出；不同场次覆盖，正常终态删除。它不替代 Dexie 的训练
状态，也不进入方案或训练历史，不引入表或永久任务。同一场次安排不匹配、记录损坏
或存储不可用时只用文字，不清空后重新播；刷新不重播准备提醒和旧组开始提醒。
累计已练时间接纳执行器产生的有限非负小数毫秒，不用整数限制误拒绝正常恢复记录。
页签内恢复推断与持久标记共同防止积压；跨设备或已关闭页签不承诺延续音频标记。

代码用实际 Vue/Pinia、训练执行器、Dexie 和外部浏览器音频/时间/网络/存储边界验证。
模拟语音开始/失败事件、音量数值或自动化录音都不是实际可听验收；小米15自带浏览器
的人耳听取、原声/倒数冲突和原先语音调整选段验收仍未完成。独立入口与默认编排器
接入也仍待完成，未改15176、正式Provider、云资源或公网入口。
本批产品代码 `7d3afd4` 的完整检查、50项 E2E、无漂移合同生成和限定范围双轴复核
均通过；历史失败尝试与最终结果分开记录，见
`docs/design/trainpal-reminder-audio-execution-20261006.md`。
