# 字幕整理句子级ASR上下文容量试点

2026-10-04，#6/#37，基线918059a。208秒隔离试点在整理前超过64KB，未调用模型。
零网络合成对照（19观察/110字幕/80语句/1120逐字项）显示ASR序列从78434字节
降至完整句子加起止时间的8074字节；原输入在HTTP前超限，仅移除重复逐字数组的
同例请求35724字节、110字幕全部保留。本例不是实际208秒逐项剖析。

## 隔离决策

- `sentence_only_visual_context=True`显式启用且要求独立字幕；默认关闭，工厂/API/
  演示不接入。不换Provider、不加调用/重试、不提高300秒或64KB限制。
- 只从字幕整理的ASR上下文移除逐字时间数组，完整语句文本、句子起止时间、顺序
  全部保留。整理只判断已有视觉字幕的用途和归属，ASR仍不能成为视觉提醒出处。
  该阶段不选择/生成ASR时间，完整句子足以表达原有上下文合同；真实质量仍须验证。
- 完整原输入（包括逐字字段、run/source/version、观察与字幕）仍参与SHA256绑定，
  非有限JSON数值仍拒绝。投影后冻结快照与带ID请求分别执行原64KB限制；不按
  总冻结副本的逐字开销误拒绝实际小于限制的模型上下文。不截断原句或字幕。
- 不修改调用方输入。原始逐字ASR仍留在本次请求原链路，不永久保存。迟到旧响应
  即使只有逐字元数据变化也不接受。原容量/时间/引用/用途/局部隔离校验继续。

## 验收

沿用Provider HTTP→来源判断边界，先红后绿。验证全部句子/时间完整、输入未修改、
原始逐字信息变化仍拒绝旧绑定；关闭态、超长句子、非法时间/NaN仍失败且不调用。
完整check/API/E2E与双轴审查，真实208秒检验能否进入整理；68秒追加固定提醒
选择计数定位丢失节点，不把容量通过等同于识别质量通过。
