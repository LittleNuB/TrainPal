# 可定位的来源关联错误局部隔离试点

2026-10-04，用户确认局部隔离方案，#6/#37，实现基线9b93ee1。
补充ADR0051的整批降级范围；仅显式开启，不接正式工厂或演示入口。

- `isolate_invalid_references=True` 才局部隔离，默认保留原整批失败行为。
- 先验证响应和全部成员恰好分配一次；缺失、重复、陌生成员、来源或绑定错误，
  超时、Provider失败及容量不足仍整批失败。不猜测或补写引用，不自动重试。
- 预告/回顾没有目标、目标不存在或不是正式组时，该组原观察全部待确认。
  正式组/其他非参考组误填关联字段时也隔离该组，不能忽略字段后继续接受。
- 隔离组不生成提醒、不进入有效目标表，原参数、冲突和来源原样保留。
  依赖它的参考关联继续按原目标未通过规则保留待确认；共享来源也不能经它放行。
- 其他组仍经过原身份、时间、编号、变式、再次执行、参数冲突及提醒审核。
  隔离观察仍参与组外视觉边界检查，不通过删掉坏组扩大别组接受范围。
- 明确返回部分关联失败警告，不报告整批成功去重。新增固定计数
  `reference_invalid_link` 按被隔离的直接错误组计一次，0–200整数；不记录内容或ID。
  下游参考拒绝沿用`reference_rejected/reference_target_unresolved`，不计为同一直接错误。

## 验收

沿用Provider HTTP→候选融合公共接口。先红后绿验证单坏引用不清空独立正确组提醒；
覆盖无目标/未知目标/自指/参考链、正式组误填引用及依赖拒绝、全局成员完整性、
编号/再次执行/时间边界与参数冲突，以及关闭态兼容。完整check/E2E/API及双轴审查。
然后在同次真实上游证据上比较关闭/开启态，沿用同一次模型分组结果，不重复收费融合，
原句及模型结果只驻留本次内存，保存固定计数与脱敏质量结论。合成通过不代表Goal完成。
