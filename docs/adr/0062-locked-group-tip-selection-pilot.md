# 锁定动作后的独立提醒选择试点

状态：2026-10-03 用户批准默认关闭的隔离试点；关联 #6/#37。
补充 ADR-0057，只在显式构造试点时取代其一次调用限制，不批准产品默认接入。

## 决定

- `SemanticCandidateFusion` 可显式接收 `tip_selection_model`，缺省为 None。
  隔离实验传入与分组相同的 Ark 客户端；不改工厂、环境设置、外部接口或演示。
- 第一阶段只判断动作身份，输入中的提醒列表为空；原观察、编号、参数、视觉描述
  和可选名称参考保留。第一阶段输出的提醒选择一律不使用。
- 先执行现有完整分组校验。仅已通过身份、时间等保护的 exercise 组进入第二阶段；
  uncertain、拒绝组、预告/回顾不成为提醒目标。参数冲突仍保留不同值及来源。
- 最多再进行一次同 Provider 文本调用，接收完整观察序列及锁定目标组，只返回每组
  最多三个已有提醒 ID。输入是数据，不是指令；上游挂靠不等于正确归属。
  无可靠语义归属则返回空列表，不借用其他组的提醒，不补写原话、时间或训练参数。
- 第二阶段的组和提醒 ID 带本次请求随机域。缺目标、重复/未知组 ID、额外输出字段
  或结构错误使本次提醒审核失败；某组的未知/跨组/重复提醒 ID 只清空该组提醒。
  无提醒的组不增加请求；有合法提醒的其他组仍可保留。
- 两阶段共用融合时间预算，第二阶段不能重置预算。不自动重试；第二阶段失败、
  超时、输入超限或预算不足时保留锁定动作及全部参数/出处，提醒为空并给固定警告。
  取消继续传播，不伪装成完成。原文、提示和响应只留内存，不新增持久存储。
- 第二阶段最终提醒仍经既有来源类型、原观察时间、安全及最多三条限制校验。
  这不是人工语义核验，不能保证模型选择正确，也不修复上游误识别或漏识别。

## 验收与实验

沿用用户已确认的 Provider 输出 → 候选融合公共接口，在 HTTP 外部边界替换响应。
先复现两阶段需求，再覆盖默认单阶段、完整原句/时间保留、错误与取消、跨组/跨请求
引用、动作锁定、参数冲突、不同编号/再次执行/变式、无提醒跳过和总预算。

真实比较复用同一份瞬态上游证据，保持同 Provider、模型和其他开关相同；记录
动作分组波动、重复/漏失、提醒出处与归属限制、阶段耗时、调用数和可取得的 token
用量。先验证 208 秒的重复候选问题，再验证 68 秒及 39 秒四动作反例。
成功运行不等于质量通过；不据此宣布准确率、P95、默认启用或完成整轮真机验收。
不推送、合并、部署、切换正式 Provider、扩大 300 秒上限或改变演示入口。
