# TrainPal 竞赛 Web MVP 产品规格

Status: frozen for Vue design v1 / GYMTI v1 competition candidate

Updated: 2026-07-23

Primary viewport: 390×844；同时支持 320px、平板和真实桌面响应式布局

Audience: 评委、现场访客、产品、设计、Web/API 开发与测试人员

## 1. 产品目标

TrainPal 是独立 Web 训练产品，也是用户可见的唯一 Agent 与小猫教练身份。它把用户已经找到并有权使用的健身视频转成一场可编辑、可立即执行的训练，并在训练中提供有出处的动作要点、低成本反馈、休息召回和陪伴成长。

竞赛主路径：

`本地选择视频 → 显式开始分析 → 内容理解与训练编译 → 查看基础方案 → 可选个性化调整 → 执行训练 → 查看结果与成长反馈`

“刷到就是练到”是价值主张；当前真实入口仍是用户保存或拥有视频后本地选择。演示不得伪装抖音分享入口、平台合作或已经调用未开放的 AI 抖音接口。

## 2. 产品边界

### 必须完成

- 本地 MP4、MOV 或 WebM 导入；五条已授权受控视频按时长排列，提供快速真实分析与环境兜底。
- 用户显式触发的整段内容理解，真实展示阶段、覆盖和错误状态。
- 内容理解结果编译为基础方案，可靠动作可执行，待确认动作默认排除。
- 动作编辑、跨视频追加、手工创建、唯一当前草稿、另存为和训练恢复。
- 可选的 TrainPal 个性化差异提案；用户值高于所有建议。
- 次数型与时长型训练、休息、暂停、跳过、提前结束和结果记录。
- 动作要点、TrainPal 五种呈现状态、隐藏偏好、休息召回和一个成长里程碑。
- 约卡路里、完成结果、海报与分享/下载兜底。
- 移动端完整可用，桌面端使用真实响应式布局。
- GYMTI 版本化题库、七猫单一推荐、明确确认、Ark／豆包最小数据增强和不阻塞的本地降级。

### 明确暂缓

- 抖音小程序、信息流内入口、任意 URL 抓取、Cookie 或登录态复用。
- 账号、服务端训练数据库、跨设备同步和长期后台任务。
- 实时姿态纠正、动作质量评分、伤病诊断、康复处方和自动负重。
- 开放式私教聊天、训练中持续模型推理和服务端 Web Push 调度。
- 用户自定义小猫形象、社交社区、排行榜和完整健身周期处方。
- DeepSeek 参考原型、第二套问卷运行时或 iframe；`questionaire/` 不进入根工作区测试、源码包、容器或线上服务。

## 3. 页面与导航

| 页面 | 路由 | 唯一主任务 | 主操作 |
| --- | --- | --- | --- |
| 首页/导入 | `/` | 选择本地视频或找回最近项目 | 开始分析 |
| 分析任务 | `/analysis` | 查看并控制当前分析 | 查看训练方案／重试 |
| 方案编辑 | `/plan` | 校正、编排并确认本次训练 | 开始训练 |
| 个性化 | `/personalize` | 完成可选资料并查看差异提案 | 应用这次调整 |
| 训练中心 | `/train` | 找回当前方案、未完成训练与已存方案 | 继续训练／打开方案 |
| 训练中/休息 | `/training` | 完成当前训练步骤 | 开始本组／完成本组／准备好了 |
| 结果 | `/result/:recordId` | 查看实际完成与成长反馈 | 分享／下载 |
| 我的 | `/mine` | 管理记录、档案、教练、成长和设置 | 打开所选模块 |

顶层导航只有 `首页 / 训练 / 我的`。分析、方案、个性化、训练和结果属于沉浸式子流程，不显示底部导航。存在未完成训练时，其他页面显示统一的轻量“继续训练”入口；存在运行中分析时显示统一的分析状态入口。

## 4. 核心行为

### 4.1 首页与本地视频

- 首页只有价值主张、视频选择、轻量预览、当前能力边界和少量最近项目，不模拟内容 Feed。
- 选片不会自动分析。用户点击“开始分析”后只创建一次运行并进入分析页。
- 原视频保存在当前设备；服务端副本和派生材料只用于本次分析并按安全合同清理。
- 文件或时长超出当前部署能力时，在上传前给出明确限制和替代操作。
- 公开真实分析不要求评委码；同一时刻只接纳一条，不设置会话／IP 冷却或次数额度。容量占用时显示稍后重试，不进入队列；终态清理后同一会话可立即再次创建。

### 4.2 分析与覆盖

- 页面展示真实阶段、`processed_seconds / source_duration_seconds`、暂时动作数、取消和恢复。
- 页面切换、刷新或短暂断线不取消任务；用户主动取消、更换来源或达到安全边界才终止。
- 终态覆盖只能是：
  - `complete`：检查完整视频，不承诺每个判断绝对正确；
  - `partial`：返回可靠动作并列出覆盖缺口；
  - `insufficient`：没有足够可靠证据形成基础方案。
- 静音或没有字幕不能单独构成证据不足，视觉理解仍必须运行。
- 覆盖缺口显示在动作列表外并允许重试；系统错误不得伪装成“没有动作”。

### 4.3 基础方案

- 训练编译按来源顺序生成完整基础方案提案；用户不再先处理独立候选收件箱。
- 可靠动作默认纳入；动作身份、范围或训练方式存在关键歧义时，原位显示待确认动作并默认排除。
- 来源片段默认只作参考播放；只有可靠来源节奏才展开为执行步骤。
- 没有可靠节奏时，同动作、器械和变式的重复演示合并；节奏内重复动作保留真实执行顺序。
- 缺失参数由版本化规则补全，字段来源是 `video | rule | personalized | user`；重量只允许用户填写。
- 用户可以修改全部可执行字段，用户修改始终优先。
- 方案页使用摘要列表；完整编辑、来源、证据和要点在 Bottom Sheet 中按需展开。

### 4.4 个性化与动作要点

- “让 TrainPal 调整这次训练”是非阻塞入口，用户可以直接使用基础方案。
- 用户先明确选择“更容易完成／更有挑战／控制用时”，再查看组数、次数或时长、休息的完整字段差异。GYMTI 不自动决定意图，教练风格不参与数值调整。
- 个性化只返回字段级差异，不重写动作结构、不覆盖用户值、不生成重量。
- 首个确定性策略只调整 `rule | personalized` 来源；`video | user` 锁定，休息只可增加，方案预计时长变化不超过 ±20%。
- 基础方案变化使旧提案不可应用；GYMTI、教练风格或可选个人信息变化只提示基于旧了解。
- 动作要点每个动作最多三条，依据只能是 `video | web | model`；网页内容保留可点击引用，模型知识明确标注为 TrainPal 通用建议。
- 动作要点补充不阻塞方案或训练；训练中不联网和不重新生成。
- GYMTI 的 Ark／豆包增强只接收稳定 ID、服务端派生信号和已经成立的结构化结果，使用独立三并发门；第四条并发或模型失败立即使用本地选题／模板，不占用真实视频分析槽。

### 4.5 训练、休息与反馈

- 训练页使用视频、当前任务和单一主操作；视频保持原始比例并使用 `contain`。
- 次数型由用户确认完成；时长型由前台计时完成。页面隐藏时活动训练自动暂停。
- 休息使用绝对截止时间，结束后进入“准备继续”，绝不自动开始。
- “太累 / 刚好 / 太轻”每个动作最多主动询问一次；确定性调整只影响本场当前动作剩余安排并由用户确认。
- TrainPal 不覆盖视频或主操作；训练阶段最多显示一条当前要点，休息阶段与倒计时成为视觉中心。
- 疼痛或眩晕只提示停止训练并寻求专业帮助，不生成训练调整。

### 4.6 结果与成长

- 结果记录实际完成动作、时间、计入休息和约卡路里；提前结束不补记未完成内容。
- 完整结束生成海报；提前结束只生成结果摘要和记录。
- 每个本地自然日有至少一个实际完成动作时计为一个有效训练日，同日只计一次。
- 成长只解锁表达、动作或纪念反馈，不改变 Agent 权限、训练参数或安全边界。

## 5. 视觉与响应式合同

- 首页、方案、个性化、训练中心、我的和结果采用温暖训练手账；训练中采用深色高对比舞台。
- 不使用固定手机壳、抖音右侧操作栏、强制 9:16 舞台或全站霓虹黑底。
- 390×844 为主要设计视口，同时完整支持 320px、平板和 1440px 桌面。
- 关键触控区域至少 44×44 CSS px，处理安全区、软键盘、键盘焦点和低动效。
- 每页只有一个视觉主操作；完整字段、证据、要点、危险操作和历史明细按需展开。

## 6. 结果状态

| 状态 | 用户可见信息 | 后续操作 |
| --- | --- | --- |
| 分析成功 | 覆盖状态与基础方案已准备好 | 查看训练方案 |
| 部分覆盖 | 可靠动作、缺口范围和非阻塞警告 | 查看方案、重试缺口 |
| 证据不足 | 没有形成空方案 | 重试、手工创建动作 |
| 系统失败 | 明确未完成分析，不归因于没有动作 | 重试、返回首页 |
| 容量繁忙 | 明确当前容量不足，不进入无期限队列 | 稍后重试、快速体验 |
| 未完成训练 | 说明本机已保存进度 | 继续训练、明确结束 |
| 提前结束 | 展示实际完成且不羞辱用户 | 查看记录、再练一次 |

## 7. E2E 验收

1. 本地选择视频，显式触发一次真实分析，离开页面后恢复同一任务。
2. `complete / partial / insufficient / failed / busy` 使用不同文案和操作。
3. 可靠动作形成基础方案，待确认动作默认排除；用户可以自由编辑并刷新恢复。
4. 用户可以直接训练，也可以进入个性化步骤流并整体应用差异提案。
5. 完成次数型与时长型动作；休息离页继续，结束后必须主动准备继续。
6. 轻反馈只调整当前动作剩余安排，不修改已存方案。
7. Pet 隐藏、资源失败和联网要点失败均不阻塞训练。
8. 完整训练生成结果与海报；提前结束只记录实际完成。
9. 320、390、768、1440 宽度无横向溢出，主操作可见且触控有效。
10. 生产构建不包含设计画廊、测试 Provider 或假 Agent 回退。
11. 公开分析验证全局单并发、并发第二条 `capacity` 429，以及同会话终态清理后立即再次获得 202；GYMTI 验证三条模型并发和第四条立即本地降级，两者并发门互不影响。
