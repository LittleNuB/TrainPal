# 同输入真实复测与收口门槛

基线 #34 / `c0102bc`；关联 #6/#9/#21。用户批准继续准备完整复测，收费执行单独确认。本批仅增加本地复评工具与验收合同，不修改产品运行代码、Provider、提示词或接受规则。

## 比较方法

- 沿用已批准的完整分析管线及融合公共接口。每个视频只生成一次上游证据与一次逻辑语义分组；现有 Provider 自身的有限重试策略不改，不自动重跑整次分析。
- 在内存中让当前融合与“相同融合代码、仅替换为 a294f0f 的旧编号解析规则”使用同一输入和同一模型分组。离线基线必须检查模型输入完全相同，不得调用 Provider。
- 这是编号解析策略的受控对照，不是完整旧构建或旧模型 A/B。两边使用相同当前代码，差异仅为 ADR-0056 的序号写法扩展；输出带明确基线策略标识。
- 不写出原始转写、标签、视觉描述、分组成员或模型响应。只保留最终产品结果和非内容计数；临时媒体在成功、失败、取消后清理。工具不进入产品导入图，不添加生产日志字段。
- 工具是一次性适配器，同一个实例不可再次运行；异常及取消始终恢复原模型引用并释放捕获数据。模型失败或预算不足时报告对照不可用，不编造基线结果。

## 固定诊断分类

仅对结构有效的正式动作分组计数；每组每类最多一次，取值 0–200。未知成员或非法参考结构时不做标签分类。

| 字段 | 含义 |
|---|---|
| format_equivalence_resolved | 旧规则认为标签不同，新规则认为同一编号；不等于最终一定成功合并 |
| different_parsed_numbers | 新规则可以解析出两个以上不同数字；不证明真实视频有不同动作，也不证明上游读错 |
| unparsed_identity_present | 新规则仍认为编号身份冲突，且包含未识别格式；不自动去除修饰 |

后两类可以同组出现，不能把分类计数相加当成拒绝组数。诊断不保存具体数字、标签或分组身份，因此不据此绑定某个动作下结论。对照另记两边候选、待确认、参数冲突组及既有拒绝原因计数。

## 收费预算和停止条件

拟申请最多四次：eval-08（208 秒）一次；通过下述第一道门槛后，才各跑 eval-07（68 秒）、eval-09（100 秒）、eval-10（39 秒）一次。任何失败或超时不自动重试；若存在明确回归，停止后续运行。授权到账前只做离线测试。

### 第一道：eval-08

- 对照冻结参考：四项主要力量动作各有一个身份明确的独立条目，没有同次示范的重复执行条目、漏项或明显来源错配。
- 教学准备/姿势说明不变成多余独立执行；热身/拉伸细分仍按 U 单列，不用不确定项凑动作匹配率。
- 同动作不同参数保留在一个待确认项的冲突结构中，各值有各自来源；不静默选值，不把待确认减少当成功标准。
- 默认回看为有效原始范围，完整来源未丢失；返回要点逐条核对来源语义，未核实的明确标记，不能仅凭时间合法声称提醒正确。
- 发现任何上述明确问题即未通过，停在本视频形成原因报告，不继续后面三次。complete 只表示覆盖，不能替代质量判断。

### 第二道：回归样本

- eval-07：主要动作去重、热身粒度与不同动作来源绑定。
- eval-09：去重、默认范围、末项参数是否错误继承、每部位与整体时长口径。
- eval-10：用户确认的四种动作分别保留，不因同器械或编号归一误合并。单视觉待确认不作为失败，也不放宽确认条件。
- H/A/U 沿用冻结记录；无逐帧/人工真值的字段不包装成确定准确率。这四次不足以完成稳定性评估；后续重复次数依据结果另行确定并授权。

## 产品与交付门槛
