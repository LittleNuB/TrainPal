## 结论

本轮使用 3 次真实文本调用：正常双来源、明确上一动作收尾两个案例通过；第三个“过渡字幕归属不明”案例失败，立即停止，后三例未运行。没有自动重试，也没有继续消耗剩余授权。

这证明现有链路已能让模型审核并排除明确错挂的要点，但面对明确描述为证据不足的归属，仍可能保留不应进入训练提醒的内容。要点归属质量门槛未通过，不能宣布真实分析问题已解决。

## 失败含义

第三例构造了相邻动作重叠的过渡时段。输入明确说明该段字幕不能确定属于哪个动作；预期保留当前动作中有可靠归属的提醒，排除过渡字幕。实际保留了正确提醒，同时多保留一条归属不明的提醒。

因此，失败不在“正确要点全部被丢弃”或“动作参数被改写”，而在当前链路仍接受了证据不足的要点。稳定 ID、组内归属和时间包含检查只能防止结构性越界，不能替代语义归属判断。本次定位到该能力缺口，但不能据此推断所有真实视频失败都具有同一原因，也不能确定只改提示词即可解决。

建议下一小批优先设计可检验的不确定性传递与拒绝机制，检查输入能否明确表达归属不足、审核结果能否保留这一状态，并继续通过公共接口验证。不要仅放宽确认标准、删除全部提醒、换模型或增加 Agent 后就宣称修复。实现和新增收费复测另行确定；本报告没有改动产品规则。
