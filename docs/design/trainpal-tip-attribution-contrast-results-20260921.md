## 结论

三种方式均未通过“转场字幕归属不明”案例。对于“明确上一动作收尾”案例，仅 B 要点分列这一次通过，A 与 C 失败。没有证据支持直接增加 Agent、采用独立审核节点或将 B 切为生产默认；也不能认为输入表示与任务负担完全无关。样本和重复次数不足以证明稳定性或唯一根因。

当前能够确认的是：在本轮两个固定构造案例上，现有模型即使拿到明确上下文，仍多次认可不应进入当前动作的提醒；单纯分列输入或提供正确动作分组，都没有形成可靠改善。真实质量门槛仍未通过。

## 对假设的影响

1. **“只要把要点从动作下面拿出来就能解决”不成立。** B 对归属不明案例仍失败；另一个案例单次通过只是后续研究信号，不足以选型。
2. **“给模型减轻分组任务就能解决”不成立。** C 已给定正确分组，两例仍失败。本实验不是完整 Agent 测试，不能推广成所有多阶段方案都无效。
3. **上轮基准单次通过不代表稳定通过。** 明确上一动作收尾案例在前轮基准中通过，本轮 A 失败。虽然构造输入和生产提示词未改，本轮没有控制服务端模型修订或随机性，不能据此单独定位波动原因。
4. **证据不足不是这个实验中唯一可以断定的根因。** 两例文本已分别明确给出“无法确定归属”与“上一动作收尾”的上下文，模型仍可能选择错误提醒。不能将问题简单归咎于 ASR、抽帧、缺少视频或未接通代码审核；这些阶段没有参与本次实验。

## 后续建议与边界

不将 B/C 升为正式链路，不追加本轮调用，不马上重跑完整视频。下一步应先定义可核验的正向归属依据：什么证据足以让一条提醒进入当前动作、什么情况必须保留为未知，以及这些信息如何从上游传递下来。区分“句子内容可信”和“属于当前动作可信”，避免继续用“未发现明显矛盾”代替“有明确支持”。该建议仍是待设计方案，不是已经验证有效的修复；不能用关键词过滤替代语义核验，也不能靠删除所有提醒过关。

本轮只记录实验结果，没有改生产实现、提示词、Provider、前端或演示入口。没有合并、部署或开放网络。真实视频质量复评、完整旅程、小米真人语音及干净主分支验收仍未完成。
