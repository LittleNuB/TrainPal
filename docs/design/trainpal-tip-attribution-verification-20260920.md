# 来源要点归属审核：离线验证记录

基线 c14bc66（Draft #35）；实现 84ab676、47a6178，规格 ADR-0057，关联 #23/#6。本批针对分析链路的要点归属缺口，不做视觉重构或 Agent 架构扩张。

## 改变了什么

原链路只让文本模型判断动作分组，要点由代码从成员直接汇集。本批让同一次模型请求同时看到带稳定 ID、类别和时间出处的短要点，输出本组认可的原要点 ID。代码校验成员归属、唯一性、类型、时间范围，输出仍为原文及原出处，不让模型重写内容或参数。跨组错挂的提示不自动搬运，无法确认就不进入提醒。

动作身份审核和要点审核是不同判断。原有动作编号、不同变式、再次执行、参数冲突与来源范围保护不放宽。融合失败或分组被拒时保留待确认动作，但不透传未审核要点。旧方案读取和已保存要点没有迁移或重写。

## 测试证据

- 先通过现有候选融合接口复现：模拟模型只认可正确要点，旧代码仍输出上一动作的收尾提示。修复前 1 项失败，修复后通过。
- 再固定不确定、Provider 失败、无剩余预算、无效成员四种失败路径，修复前 4 项失败，修复后均不泄漏未审核要点。
- 原始出处越界/类型错误的三种用例先失败，再补来源校验使其通过；没有通过修改时间阈值修复。
- 新增专项最终 26 项通过，含单次外部请求携带要点、漏选、未知/重复/跨组 ID、超时、相邻动作、预告/回顾、不同编号、再次执行、输入预算及参数冲突仍保留两种值。现有语音原文出处校验继续通过。
- 首轮完整 `pnpm check` 通过：前端 275、后端 985 项。审查修复后最终完整复跑为前端 275、后端 989 项，lint、严格类型检查、生产构建均通过。E2E 两轮均为 49 项通过，包含要点随编辑、归档、刷新和跟练保留的既有用例；最终接口重新生成无内容差异。

## Standards

初审 c14bc66...84ab676 发现 1 项明确 P2：要点选择超过三条时在整份响应解析触发失败，导致已有效动作分组全局回退，违反 ADR-0057 的局部降级要求。启发式问题 0。

47a6178 先以超限、null、字符串、非字符串列表四项公共接口测试复现，再将这类非法选择局限为本组空要点，保留模型 schema 最多三条。复核 c14bc66...47a6178：原 P2 关闭，明确违规 0，启发式 0；独立专项 26 项通过。

## Spec

初审独立发现同一 P2；其余一次调用、来源保留、编号/重复执行/参数保护、旧方案兼容无发现。复核 c14bc66...47a6178：P0/P1/P2 均为 0，独立专项 26 项通过。真实模型归属判断能力仍待单独验收。

两轴最终剩余发现：Standards 0、Spec 0，无未解决最高级问题。

测试只在外部 HTTP 模型边界替换响应，执行真实融合与校验代码；没有把私有方法的返回值作为回归验收。之前的临时诊断脚本仅留在忽略目录，不进入交付。

## 不代表什么

上述测试证明程序能遵守审核决定、阻止越界和失败透传，不证明真实模型一定能判断对提醒归属。模型只看结构化证据，不重新观看媒体；上游与审核同时误判仍可能产生错误。此次没有真实 Provider 调用，也没有新增媒体处理。

逻辑请求阶段未增加，但同次请求的输入更长；耗时、预算命中率及是否影响动作分组质量尚未实测。没有宣称总体准确率、稳定性、性能达标或已修复真实视频的全部问题。

下一步应先用有明确答案的固定短文本案例验证实际模型的归属判断，再考虑完整视频复测。收费调用须另行确认；此前条件式四次预算已因首条质量失败停止，本批没有动用剩余三次。不得因要点缺失而掩盖未解决问题，也不以“返回空提示”统计为正确识别。

本批只产出独立 Draft PR，不合并、不部署、不开放网络，现有演示入口不更新。实际结果完整旅程、小米自带浏览器真人语音和干净主分支验收仍未完成。
