# 融合拒绝原因诊断规格

用户在两次真实复评未通过后批准继续定位原因；关联 #6，基线 #32 / 29fc835。本批只增加非内容诊断，不修改融合接受条件、提示词、Provider、接口或确认策略，不新增收费调用。

## 合同

- 沿用已确认的融合公共接口。内部 `SemanticFusionResult.diagnostics` 提供固定枚举原因到非负整数的计数，不加入 HTTP/SSE、动作方案或永久用户存储。
- 对每个正式动作分组同时检查全部适用条件：模型不确定、非正式动作角色、编号身份冲突、时间护栏未通过。无共同交集时细分：视觉数量不足、非明确教学视觉、跟练观察、视觉间隙或仅接触、组外视觉边界、语音不覆盖视觉。已有共同交集时不报告不适用的教学例外限制。
- 一个分组同一原因最多计一次；多个原因可并存，原因总数不等于拒绝分组数。单独计 `group_rejected`、共同交集接受、连续教学接受、已接受但有参数冲突，以及非训练排除和参考关联。
- 参考关联失败单独计数，区分目标未成功解析、不确定、角色保护、编号、参数和时间方向；不混入正式动作参数冲突。
- 全局不可用按输入预算、剩余预算、模型超时、Provider/结构错误、ID 完整性或关联目标结构错误分类。取消继续传播，不伪装失败诊断或吞掉取消。
- 同一结构化计数经专用过滤进入现有安全日志：只允许固定原因码及 0–200 的整数，拒绝任意键、文本、布尔值、负值与过大数值。日志不包含名称、原始编号、时间段、证据正文、分组成员、转写、模型原文、路径或凭据。除本次原因计数外，不扩大其他日志字段。

## 验收与限制

先以编号冲突复现“结果保留但无法得知原因”，再逐项覆盖时间例外、同时多原因、原共同交集、参数冲突、参考关联和失败取消。验证结果和原始证据不变；安全日志只能含白名单结构。完整检查、E2E、Standards/Spec 双轴审查后提交依赖 #32 的独立 Draft PR。

此前未保存的真实分组无法被这些诊断事后还原。本批不声称已确定 208 秒视频的具体拒绝原因，更不以合成测试证明真实去重改善。若需要新的真实诊断，另行申请调用授权。
