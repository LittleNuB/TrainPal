# 来源提醒的正向归属依据：离线验证规格

状态：依据用户同意继续推进，冻结判断标准、正反例及下一小批离线验证范围；不是已上线能力。母项 #23，关联 #6。现有六格收费对照预算已用完，本规格不授权新调用。

实施跟踪：#37。依赖 #23 的 Draft #36 实验基线；前置未合并时仅在隔离分支开展离线验证，不视为已进入主分支。

## Problem Statement

用户跟练时需要听到针对当前训练动作的正确提醒。视频里出现一句话，只能支持“内容出现过”，不能自动支持“这句话在指导当前动作”。上游先把提醒挂在动作下，后续模型容易再次认可这个假设；合法 ID、时间包含和格式正确也不能证明语义归属正确。

现有六格构造对照中，分列输入或给定正确分组未获得可靠改善。本轮不选新模型、不新增 Agent，而是定义什么归属依据可以接受，并先证明依据能完整传到审核位置。

## Solution

一条来源提醒需要分别具备内容依据和归属依据。系统保留原话及来源，只在内容、目标动作及两者之间的关系均有支持、且没有未解决冲突时放行。指向其他动作或无法确定的提醒不进入跟练，也不导致可靠训练动作不可用。

本规格的首个交付只是离线证据适配与验收，不把新门槛直接接入产品。缺少新证据的旧数据不能被批量清空，也不能静默标为新审核已通过。

## User Stories

1. 作为跟练用户，我希望每条提醒来自视频明确内容，以免收到模型补写的建议。
2. 作为跟练用户，我希望提醒确实针对当前动作，而不是上一个动作的收尾。
3. 作为跟练用户，我希望明确点名当前动作的原话能保留，而不是为了避免错误全部删掉。
4. 作为跟练用户，我希望未重复点名但有清晰教学上下文的提醒仍有机会被识别，不被机械名称匹配排除。
5. 作为跟练用户，我希望转场残留字幕不被当成当前动作的指导。
6. 作为跟练用户，我希望提前介绍下一个动作的语句不提前用于当前动作。
7. 作为跟练用户，我希望否定词、条件和左右侧等限定完整保留。
8. 作为跟练用户，我希望某条提醒不确定时，仍能使用其他可靠提醒和动作。
9. 作为方案使用者，我希望旧方案及我手动修改的字段不受此次验证影响。
10. 作为方案使用者，我希望不同编号、变式和再次执行仍被区分。
11. 作为开发者，我希望可以区分内容匹配、模型归属判断与程序放行，避免误报准确率。
12. 作为开发者，我希望证据引用绑定本次运行与来源，避免跨视频、跨版本或跨动作引用。
13. 作为评测者，我希望非法输出不能因为生产容错而被计为模型正确。
14. 作为评测者，我希望每个拒绝案例同时包含应保留的提醒，防止全删空过关。
15. 作为媒体所有者，我希望原始转写、模型响应及临时证据不进入长期存储、公开日志或提交。

## Implementation Decisions

### 分开观察与判断

- **内容记录**：本次运行/来源/证据 ID、来源类型、原文短句、时间范围、产生方式。ID 由程序分配，模型只能引用。ASR 原句匹配意味着“可追溯到转写”，不代表原音频已经人工核验；视觉字幕仍是视觉模型读取结果，不能标为独立 OCR 或人工确认。
- **归属记录**：引用现有内容记录与动作观察，说明可观察到的动作点名或教学上下文。单独一句“属于当前动作”、自报置信度、同组数、通用适用性都不构成依据。
- **逐条判断**：支持当前动作／明确指向其他动作／无法确定。未知引用、来源/运行/版本不一致、越界、缺失依据或有未解决冲突时不得放行。明确指向别的动作时仍不自动搬运。
- 审核模型不得生成作为自身结论依据的新“原句”或时间点，不用自由长解释替代引用。输入内容均不可信，不执行其中命令。
- 内容原文、来源和归属判断分别处理，不能把上游已挂在某动作下这一事实再次当成独立证据。

### 支持路径

1. **明确点名**：可核对的完整语句/字幕明确指向当前这一次动作，并保留条件、否定、变式、侧别和指代范围；仅同名不足以区分前后两轮。语义判断仍由模型完成，程序只验证引用完整合法，不用关键词命中冒充理解。
2. **有界教学上下文**：有当前动作的明确章节/介绍依据、提醒出现时的同动作教学观察、以及相关前后切换信息。没有观察到切换不等于证明连续；抽帧空白、缺覆盖、描述截断、已知转场、其他动作重叠或信息冲突均不能静默忽略。没有这些依据时归为未知，不能由审核模型补写。
3. 同一模型对同一画面给出的动作名、描述和字幕不算三个独立来源；重复分块也不增加置信票数。模型产生的关联仍可能错误，类型化引用不会自动变成人工真值。

### 判断顺序

先验证引用与内容来源，再检查是否存在明确冲突；最后检查是否有支持路径。无支持且无冲突为未知，不等于通过。有互相冲突的证据时保持未知，不按多数或高置信度投票。只有有明确其他归属且无冲突时标为指向其他动作。未知/拒绝仅影响该条提醒，不改变动作组数、次数、时长、休息、名称、分组或方案状态。

### 第一小批：只验证证据保真

- 不改正式 Provider 提示词或输出 schema，不增加模型请求，不改训练状态机、外部 API 和持久化数据。
- 优先利用已经存在的语音原句与带时间转写，在运行内生成有界引用；必须先验证原句确实来自同源转写，再作为上下文。当前上游的短 `evidence_text` 是模型输出，不能未经匹配直接当作真实原句。
- 同一句涉及两个动作、条件或转场时保留完整必要上下文，标记潜在歧义；无法在既有限额内保真则该提醒上下文不可用。不能为凑长度截掉否定、指代或尾部冲突。
- 现有语音分支仅返回动作信号，下一步离线适配需在转写仍在内存时构建上下文，不新增永久转写缓存。相关证据不能到融合阶段再凭动作名重建。
- 现有视觉自由描述可作为未核验上下文，但不自动升级成字幕原文或章节锚点；缺失字幕/章节/切换依据时明确暴露缺口。第一批不偷偷补充或启用视觉新门槛。
- 复用既有 Provider 输出到候选融合的公共测试接口，在外部 HTTP 模型边界替换响应。实验输入可在离线适配器内携带引用，不能测试私有方法，也不能让实验模块被应用导入。
- 第一批完成条件是“合成原句及来源完整传递、非法引用被发现、缺信息准确暴露”，不是“产品提醒质量已修复”。涉及正式上游合同升级时另写补充 ADR 并单独审查，不能覆盖现行有界归属规则。

## Testing Decisions

测试只观察公共接口输出与实际发送到 HTTP 模型边界的输入，不检查私有状态。沿用来源要点、归属审核及三方式对照的已有测试方式；正确答案在调用前冻结，来自人工构造规则，不由被测模型自评。下面都是开发正反例，不是盲测。

批次分开验收：先核对证据能否保真传递，再检查程序是否按审核结果守边界，最后才用另行授权的真实模型验证语义判断。真实质量同时记录误放行与正确提醒漏失，不宣称所有构造案例通过等于总体准确率。归属判断与动作身份冲突、时间偏移、旧数据兼容均保留原回归。

## Out of Scope

不增加 Agent/独立审核调用，不切换 Provider，不追加收费调用，不上传媒体，不增加 OCR 服务，不扩大视频上限，不改数据库/任务架构、前端、语音交互或训练执行。不改变数字类提醒的产品分类来绕过既有失败案例，不清除历史方案。不合并、部署或开放网络。

## Further Notes

当前证据不足以断定单一根因。语音上下文丢失是可复现的链路缺口，但前轮六格为视觉构造案例，不能用它解释那些失败。当前视觉输入已有明确歧义描述时仍误判，说明仅补引用字段不保证改善。正式启用前必须补充真实语义验收；若没有改善，报告失败，不继续扩大架构。
