## 要回答的问题

1. 把要点嵌在动作下的表示方式，是否影响模型排除错误归属？
2. 在输入表示一致时，给定动作分组、只审核要点，是否改善判断？

这是受控诊断，不是新的准确率测试集。第三组有人工提供的正确动作分组，只能说明在该条件下的表现，不能直接证明增加一个线上节点有效，也不能把改善唯一归因于“模型任务过多”。

## 固定输入与预期答案

从前轮构造案例原样取两例，不使用真实视频、ASR、个人资料或原始模型响应：

- `ambiguous_transition`：两个动作、两条提醒；排除过渡时段归属不明的“坚持完成4组”，保留有明确归属的“胸部贴住靠垫”。
- `previous_action_closing_caption`：两个动作、三条提醒；排除明确来自上一动作的收尾字幕，保留两个动作各自正确提醒。

前一例内含正确提醒对照，后一例检查已通过行为不回退。动作分组、默认来源范围和参数答案也固定；本次两例参数均为空，不能声称覆盖训练参数冲突。

## 三种实验方式

| 方式 | 输入 | 任务 | 对照解释 |
| --- | --- | --- | --- |
| A `nested` | 原生产输入，要点嵌入动作观察 | 原提示词和原输出 schema | 当前版本基准，不能复用前次输出冒充本次测量 |
| B `flat` | 动作与要点分列；保留原 ID、全文、时间、类别及待核实的上游归属 | 同样完成动作分组与要点选择 | A→B 只调整表示方式及必要的格式说明，不删除不确定描述或增加答案 |
| C `flat_fixed_groups` | 与 B 相同，额外给定冻结的正确动作分组，不含要点答案 | 只判断要点，复述固定动作分组 | B→C 是给定正确分组条件下的任务简化实验，不是纯粹的提示词长度对照 |

三者使用相同 Provider、模型配置、输出 schema、生产融合与最终过滤代码。每次仅一次文本请求、无重试。B/C 的外层仍复用既有文本模型接口，但其观察列表承载一个明确标注的实验信封；动作 ID 与要点 ID 不得混为分组成员。原 ID 暗含上游绑定，因此 B 不是完全消除归属暗示的实验。

C 如果篡改固定分组，计为失败，不由工具修正后计为通过。不跨组转移提醒，不重写原文、时间、参数，不给输入追加提示答案。

## 评分与执行边界

- 比较最终动作数、分组成员/角色/关联、参数及默认来源范围。
- 分别统计应保留但缺失的提醒、错误保留的提醒；保留文字、类别、时间、来源类型及所属动作一起核对。
- 同时检查模型原始选择是否匹配预期；非法 ID 被生产代码清空也不能伪装成模型判断正确。
- 超时、Provider 错误、非法输出、分组漂移必须与普通质量失败区分。输出只存固定标识、计数、布尔值、哈希、耗时、固定诊断码，不存原始请求或模型响应。
- 工具只支持这两条冻结案例及三种方式；无配置加载、无凭据搜索、无自执行网络入口。通过显式注入 HTTP 客户端调用实际 Ark 公共接口，固定禁用 Provider 重试。单个工具实例只能使用一次。
- 离线测试使用 HTTP 边界替身，执行真实 Provider 解析和候选融合，不更改应用接口，不在生产导入实验模块。
