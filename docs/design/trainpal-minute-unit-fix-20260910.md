# 分钟单位修复：GAP-01 首批

来源：当前用户同意继续修复，以及本机差距审查中的 GAP-01。历史 eval-07 候选把 20 分钟爬坡有氧写成 20 秒。本批不修改 Provider 选型、运行架构、产品时长上限或训练执行规则。

## 范围与验收

通过 `ArkResponsesClient.understand_speech` 公共接口处理结构化响应，再经真实 `fuse_candidates` 输出候选；只有外部 HTTP 返回在测试中替代，内部处理不模拟。

- 时间戳位于对应 signal 内的 ASR 语句明确写出与动作名直接相邻的单个阿拉伯数字分钟值，且模型把原数字错误当秒数时，进行一次 ×60 换算；20 分钟对应 1200 秒。
- 已是 1200 秒的不重复换算；20 秒保持 20 秒；缺失值不自动补全。
- 不读取模型生成的 evidence_text 推断单位，不读取全片无时间的 text 兜底；不借用相邻动作的数值或范围之外的语句。
- 范围、近似、否定、复合时长、休息语境、延迟开始与视频长度不在此窄规则支持范围内，原结果不由该规则修改。这不代表这些原结果已被验证正确。
- 仅处理单一 duration 字段且没有 reps/rest 的情况；不处理休息换算、中文数字、动作别名或新的参数抽取任务。保守不匹配仍交由现有流程；不能宣称解决所有单位问题。
- 审查后进一步收紧为完整短句白名单：可选“训练后/练后、可/可以、再、加/做/进行”前缀，或已观察到的精确 ASR 前缀“晚可以加”，随后“数字＋分钟＋完整动作名”，可带句末标点。动作在时间前、复杂长句、额外限定词不自动修正。这样不靠不断扩大黑名单猜测自然语言；代价是覆盖较窄，不是通用口语单位解析。

## 证据与测试过程

历史原始响应已按隐私约定清理。测试使用同义的脱敏语句与构造的错误模型返回，不伪称历史原始响应回放。

首个接口测试实际失败 `20 != 1200`；加入边界修正后通过。随后复合时间、延迟开始、视频时长、相邻动作保护测试暴露误修正，逐轮收紧规则后通过。

该测试证明当前接口能防住这个受限输入模式，不证明此前历史请求的唯一根因就是模型换算错误。重复候选和动作错位未在本提交修复，不以模糊合并换取候选数量下降。

命令：`uv run --project services/analysis-api pytest services/analysis-api/tests/test_speech_time_units.py -q`。

## 真实语音分支复测（2026-09-10）

在用户已授权的服务和视频范围内，仅对 eval-07 全长 67.83 秒音轨复测，未调用视觉模型、未运行整条产品链路。

1. 首次复测：模型原始 duration_seconds=20，规则输出仍为 20，暴露实际句式不匹配。
2. 补核短证据：60.58–62.06 秒 ASR 为“晚可以加20分钟爬坡有氧。”。仅保留这段匿名短证据，不据此纠正其他语义或丢弃原片条件。
3. 将实际句式及其“最多”“不可以”保护用例加入接口测试，先复现失败 20 != 1200，再增加精确前缀支持；84 个定向测试通过。
4. 再次真实复测：动作爬坡有氧，60.58–62.06 秒；模型原始值仍为 20，公共 Provider 接口输出为 1200，确认此次是规则纠正而非模型恰好答对。
