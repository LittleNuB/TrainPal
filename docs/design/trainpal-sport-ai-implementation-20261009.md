## 1. 交付目标与实施顺序

交付一套真实可操作的 TrainPal 页面：可爱、轻量，有运动产品的清晰操作感；用户从视频生成方案，直接编辑训练量，也能根据自己的情况获得调整建议。

首先完成方案编辑与个性化这条核心路径，再将同一组件和信息层级铺到其他页面。18 张图是 8 个业务路由中的 11 个主要画面与 7 个状态，不建立 18 个独立路由。

| 批次 | 实施内容 | 完成后能看到什么 | 依赖 |
| --- | --- | --- | --- |
| A | 视觉规范、页面框架与少量共用组件 | 新配色、排版、按钮、数字编辑器和折叠卡片进入运行页面 | 本计划 |
| B | 训练方案与来源查看 | 动作默认收起，只展开当前动作，改数字立即更新摘要 | A |
| C1 | 个性化上下文和调整策略接入 | 训练经验、当次时间/状态、可追溯反馈真正参与调整 | B |
| C2 | 可编辑的 AI 调整预览 | 建议还可手动修改；确认一次保存，取消不改方案 | C1 |
| D | 首页、快速开始、分析与训练库 | 从选视频到可编辑方案，再到存档的完整路径 | A、B |
| E | 跟练、休息、暂停、换动作与结果 | 训练时始终看得见当前目标、主操作和暂停 | B、C2、D |
| F | 我的、资料、GYMTI 与小猫选择 | 七猫列表、测评结果和个人信息使用同一套界面 | A、C1 |
| G | 全旅程、响应式和交付验收 | 可演示版本、18 状态实屏对照、回归结果 | A–F |

C1/C2 是同一批个性化工作中的两个交付点。执行时按 A → B → C1 → C2 → D → E → F → G 推进，每批保留可运行成果。

## 2. 已通过的设计规则

1. 白色与浅冷灰底、深蓝文字、青绿色主操作；亮黄色只作少量提示。复用正式七猫素材。
2. 一屏一项主任务。首页保留视频入口，“快速开始”合并预设方案和示例视频分析。
3. 方案动作默认全部收起。同一时刻最多展开一个动作，点击另一项时切换，编辑结果保留。
4. 组数、次数/时长、休息直接输入，也可加减；名称、重量、排序等次要操作按需展开。
5. AI 通过整理结果、上下文和待确认建议体现；不增加聊天窗口或多轮问答。
6. AI 设置、动作编辑、来源查看分层出现，避免三个区域同时铺开。建议先预览再应用。
7. 小猫在标题、陪练反馈或风格选择中适度出现，主动避让输入框、视频和底部操作。
8. 桌面延续同一信息优先级，采用合适宽度与分区；动作编辑仍保持一次一个。

### 与旧规范的关系

- ADR-0085 接替 ADR-0047 的暖白/灰绿/陶土视觉，以及 ADR-0028 的“完整编辑只在 Bottom Sheet”规则。
- 本轮主参数采用卡内展开；来源、复杂编辑和低频操作仍可使用面板。
- ADR-0046 的确定性数值保护、ADR-0019 的提案版本关系、ADR-0049 的自动存档、ADR-0052/0084 的训练衔接语义继续作为实施约束。
- C 批需要新增上下文和建议编辑协议，按下面的契约补齐类型、版本和测试，不能把旧提案类型直接改成可随意修改的对象。
- 图中示例次数、时长和猫咪是展示数据。运行页面从当前方案、记录和已确认风格读取；摘要用真实数据计算。

**范围**

- `styles/base.css`、`App.vue`、`TopLevelNav.vue`、`router/meta.d.ts` 及必要的页面局部样式。
- 调整颜色、字体层级、间距、圆角、焦点和固定操作区；清理仍依赖旧配色的局部样式。
- 从 B 批实际需求抽出数字输入、动作折叠卡、来源面板、底部操作区。复用现有 `useDialogFocus`。
- 整理七猫展示方式：已确认风格用对应资产；未确认时使用普通品牌状态，不预先绑定温柔型。
- 开始实施前记录 HEAD 与工作区差异，用该固定起点核对本轮改动。
- 若切换工作树，按锁定清单复制本轮 PNG 与折叠演示并核对 SHA-256，确保实施者能读取同一套参考。

**组件要求**

- 手机正文以 14–16px 为主，普通标题约 22–24px；点击目标至少 44px。
- 青绿按钮配深色文字；正文、次要文字、禁用状态和焦点分别检查对比度。
- 数字输入支持键盘、直接输入、加减和错误提示；编辑中的空字符串与有效的 0 分开处理，按字段规则提交。
- 折叠头使用真实按钮和 `aria-expanded/aria-controls`；复杂面板有焦点约束、关闭后返回触发点。
- 小猫动作服从减少动态效果设置；底部区域处理安全区和内容留白。

**退出条件**

- 在运行中的方案页接出共用组件，390px 可操作；320/768/1440px 无横向溢出。
- 新旧 token 与局部颜色核对完毕；本批涉及的组件与导航用例通过。
- 交付首批运行截图，作为后续页面组件基线。

### B — 训练方案和视频来源（05、07）

**范围**

- `views/PlanDraftView.vue`、`stores/draft.ts` 的现有公开动作、必要的新展示组件。
- 默认全部收起；只展开一个动作。展开区只优先呈现组数、次数/时长和休息。
- 输入提交后，折叠摘要、预计时长和自动存档同步更新。
- 重量、模式、名称、排序、复制、删除、手工新增等已有功能置于明确可达的次级入口。
- 来源面板保留视频回看、证据、参数冲突、来源丢失后的重新选择；视频明确值与建议值分开呈现。
- 待确认动作摘要保留状态及核对入口；涉及其确认的必要信息可见，未经确认不进入训练或自动调整。
- 原有来源要点审核与训练提醒设置保留入口，详情默认收起。

**退出条件**

- 展开 A → 改为 11 → 展开 B → 返回 A，值仍为 11，列表摘要正确。
- 直接输入与加减操作使用同一验证和存档路径；刷新后可恢复。
- 手动修改字段标为 `user`；AI 生成不会覆盖它。
- 无效输入定位到对应动作和字段，不因折叠隐藏错误；必要时自动展开出错项。
- 慢保存、失败、连续操作与离页时的现有保护通过回归；只有保存成功才进入训练。
- 05/07 对照截图与方案编辑旅程可运行。

### C1 — 接通个性化上下文

**范围**

- `domain/personalization.ts`、`domain/training.ts`、`personalization/adjustment-policy.ts`。
- `stores/library.ts`、`stores/draft.ts`、相应 repository、Dexie 迁移与本地清除协调器。
- 训练经验由用户明确填写，可空缺；从“我的”及调整上下文中进入编辑。
- 当次可用时间、精力状态和调整方向放在一个短表单里，提交后折叠为摘要。当次输入不自动变为长期画像。
- 动作反馈使用“太累 / 合适 / 太轻”这样的结构化选择；可在结果的单动作详情内补充。
- 反馈单独关联方案、动作、场次和时间，允许修改/清除，不回写冻结训练记录。
- 首版只使用可追溯到同一动作身份与版本的反馈；仅名称相同的重新识别动作不自动继承。
- 将稳定资料、当次状态、反馈来源和版本组成上下文快照，加入提案指纹。

**调整规则**

- 保持明确调整方向，复用确定性调整模块；扩展真实上下文，不增加对话轮次或新的模型调用链。
- 训练经验和反馈参与候选选择与现有边界；“有点累”参与减量/恢复方向，可用时间参与缩短目标。
- “10 分钟”作为时间目标，显示可达到的预计时长；受现有保护无法达到时直接说明，不伪造精确达标。
- 每个自动建议仍只修改已确认动作的 `rule | personalized` 字段；`video | user`、动作身份/顺序/方式、来源和重量保持保护。
- 保留现有最大变化幅度、整份预计时长变化 ±20%、初学者限制、反馈限制及不适停止逻辑。
- GYMTI 用于背景解释与偏好；教练风格决定表达，不决定训练量。缺少历史资料时明确按当次输入处理。
- 上下文和应用协议的升级使用可识别版本；旧存档、旧提案可以兼容读取或要求重新生成，不把旧对象当作新协议。

**退出条件**

- 同一方案在不同真实输入下，产生符合规则的差异或合法的无需调整结果。
- 有反馈才显示“上次太累”；没有反馈、不匹配动作或已清除数据时不引用历史。
- 旧资料迁移、反馈身份隔离、修改/清除、上下文变更、无可调字段等用例通过。
- 调整依据可以展开核对到本次实际输入，不显示模型臆造的画像。

### C2 — 可编辑的调整预览（06）

**范围**

- `PlanDraftView.vue`、提案审阅状态和 `stores/draft.ts` 的应用/恢复动作。
- 复用 B 的数字编辑器和折叠卡。默认只展开第一个发生变化的动作，其他动作收起。
- 展示原值 → 建议值和简短依据；依据详情折叠。
- 原始提案保持不可变；建立与基础 revision/fingerprint 绑定的可编辑审阅副本。
- 用户修改只作用于审阅副本，取消整体丢弃；不得先改基础方案再试图应用旧提案。
- 用户未改的自动建议保存为 `personalized`；用户覆盖的字段保存为 `user`，按手动输入规则验证。
- 确认时检查基础方案、来源及版本，再一次性保存最终差异；原子失败不留半份应用。
- 应用或取消后回到折叠列表；恢复基础方案仍只撤销可恢复的 AI 字段，保留之后的手动修改。
- 基础方案变化使建议失效；资料变化按 ADR-0019 提示上下文过期，允许查看后选择保留或重新生成。

**退出条件**

- “AI 建议 10 次 → 手改 11 → 应用”保存 11，来源为 user；其他未改建议为 personalized。
- 取消不改变原方案；修改基础方案后旧建议不可应用。
- 刷新、重复点击、保存失败、数据清除和恢复基础方案均经过回归。
- 个性化完整路径“填写情况 → 查看建议 → 改数字 → 应用 → 开练”可操作。

### D — 输入、快速开始、分析和训练库（01–04、08）

**范围**

- `HomeView.vue`、`VideoAnalysisView.vue`、`TrainHubView.vue`、快速方案 fixture 和原有 stores。
- 首页突出导入视频，选中后显示视频摘要与生成方案主操作。
- 快速开始用同一面板承载“查看预设方案”和“体验视频分析”；后者按需展开现有五个受控来源并明确开始。
- 预设方案进入编辑器；其来源标签不冒充 AI 分析结果。
- 分析中显示真实已处理时间，候选发现收起；分析完成后先检查方案，不自动开练。
- 训练库使用个人方案列表，保留自动存档、打开、复制、删除、空列表和进行中训练入口。
- 动态数值使用 store/API 返回值，不把参考图的动作数、时间或课程文案写成运行逻辑。

**退出条件**

- 首页 → 快速开始两条分支都能走通；打开面板不产生分析调用。
- 本地选片 → 显式分析 → 查看方案可走通，取消/恢复与单次任务语义保持。
- 分析的 partial、insufficient、待确认和缺口重试可找到；失败不渲染成“没有动作”。
- 分析页和方案页的条数口径一致，已确认与待确认分开统计。
- 从训练库打开后编辑、返回列表、刷新，数据一致。

### E — 跟练与结果（09–12、18）

**范围**

- `TrainingView.vue`、`ResultView.vue`、`PlaybackControls.vue`、既有教练/提醒展示组件。
- 视频按原始比例完整显示；当前动作、组次和目标占据主要视线。
- 次数组显式“完成本组”，计时组沿用计时结束；暂停始终作为可见次级操作。
- 同动作正常前台休息到时按原规则自动倒数；首组和新动作显示“准备好了”。
- 后台、恢复、普通暂停、暂停休息沿用各自恢复语义，不因为新布局自动开始。
- 结果使用实际完成组数/次数/时长；复练返回方案，保留记录与当前草稿独立。
- 反馈入口接 C1，放在动作详情中；片段调整、要点、声音、跳过、提前结束保留次级入口。

**退出条件**

- 次数/计时、休息自动衔接、换动作准备、暂停/后台恢复、提前结束、结果与复练旅程通过。
- 视频播放结束不等于完成训练组；全场进度只计实际完成组。
- 320/390px 不滚动也能找到主操作和暂停；视频、控制区、小猫互不遮挡。
- 本轮不扩展训练状态机；界面完整接回现有执行器。

### F — 我的、GYMTI、资料和小猫（13–17）

**范围**

- `MineView.vue`、`PersonalizeView.vue`、`features/gymti/Gymti*.vue`、`ProfileForm.vue`。
- 我的页面保持训练记录、可选资料和偏好入口，接入 C1 的训练经验及相关数据管理。
- 测评一屏一题，资料可跳过；正式题目和结果文案来自版本化合同。
- 结果页使用收敛尺寸的正式插画，推荐小猫待用户确认。
- 七猫采用紧凑列表；只展开选中风格的介绍，当前使用与本次推荐各自表达。
- 继续使用正式七猫资源和可访问操作，不把新图里的温柔型硬编码为默认值。

**退出条件**

- 完整答题 → 跳过/保存资料 → 结果 → 选择/确认小猫 → 我的更新。
- 返回、重测和保存失败不会误确认风格；可选资料不影响正式测评结果。
- 七猫身份、问卷稳定 ID、正式文案及现有模型降级规则回归通过。
- 未选择小猫的用户也能完成方案和训练。

### G — 整体验收和交付

**自动化**

- 每批先运行相关 view/store/domain tests 和受影响 E2E；有行为变化的用例同时更新，不为纯样式重复建立同构测试。
- C 批重点覆盖数据迁移、来源优先级、建议失效、审阅副本、原子应用和回滚。
- 交付运行完整 `pnpm check` 与 `pnpm test:e2e`；只有 API 合同变化时生成并核对 API 差异。
- E2E 用独立 loopback 端口与测试数据，保留现有单分析槽约束。

**实屏**
