## 冻结设计

复用现有 Ark 文本模型配置，不切换正式 Provider。两组使用同一输出 schema、同一判断提示及同一个证据上下文输入格式。`legacy_visible` 只保留旧链路可见的信息：没有原始转写，视觉描述最多 600 字；`complete_context` 保留完整转写与视觉描述。

因此这是“相同实验格式下的信息完整度对照”，**不是旧产品与新产品端到端对照**。两组共同采用实验格式说明；不能把实验结果直接推断为线上准确率变化。

每条案例的动作、提醒、时间和正确答案在调用前固定，答案不进入请求。

## 这次能得出的结论

1. 信息传递缺口确实能修补，但在本批构造案例里，补全后没有减少错放提醒。
2. 完整上下文已经明确包含“针对上一动作”及否定词，模型仍选择错误提醒。因此这两例不能仅归因于证据被丢弃或截断。
3. 目前观察到的是“当前模型、任务表达和输出合同这一组合，未可靠执行逐条提醒判断”。这没有定位唯一根因，不能直接断言是模型能力上限、所有 Agent 方案无效或上下文从来没有用。
4. 原本含糊的证据仍然含糊，扩大呈现不会自动创造确定性。接下来需要检验明确的逐条支持/冲突/未知判断是否比仅返回接受列表可靠；这只是下一步假设，尚未实现或获得新调用授权。
